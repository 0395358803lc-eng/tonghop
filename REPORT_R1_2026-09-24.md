## Tách commit theo logic: chi tiết kỹ thuật không thể bỏ qua

Hai file vừa chứa sửa đổi R0 của tôi vừa chứa code feature chưa release: `backend/app/api.py`
(10 hunk, chỉ 1 hunk là của tôi) và `backend/app/film_event_store.py` (hunk cuối gộp cả
`list_recent_events` của feature lẫn khối purge của tôi). Gom nguyên file vào một commit sẽ
trộn R0 với code chưa được kiểm chứng live.

Cách tách: dựng blob = `HEAD` + đúng phần R0, rồi stage bằng plumbing
(`git hash-object -w --stdin` + `git update-index --cacheinfo`). **Working tree không bị sửa một
chút nào**, nên nội dung đã test vẫn còn nguyên để commit ⑤ lấy tiếp.
Kết quả commit ④: `api.py +9/−2`, `film_event_store.py +43`, và
`git diff --cached | grep -c "CANONICAL_RUN_QUEUED|list_recent_events"` = **0**.

Bẫy đã gặp và sửa: lần chạy đầu dùng subprocess text-mode, Python dịch `\n`→`\r\n` khi ghi vào
stdin của `hash-object`, làm blob staged lệch **toàn bộ 2695 dòng** so với HEAD. Phát hiện nhờ
`git diff --cached --stat`, `git reset` index và viết lại bằng binary I/O. Nếu không kiểm tra stat
sau khi stage, commit ④ đã chứa một file đổi line-ending toàn phần.
